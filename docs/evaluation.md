# 編集の正しさの評価（#345 D7）

実際の素材で「無音を削る」「話の区切りで分ける」「場面ごとに切る」「字幕を付ける」を、
人の編集（正解）と比べて、一致率とかかった時間を数える 変更の前と後で数を比べ、
精度が上がったか下がったかを確かめる 短い素材 2 本では「字幕を焼き込んで書き出す」も行い、
書き出した動画を `check_output` と同じ検査に掛けて、見つかった問題の数を数える

「見どころを選ぶ」（#414）は、人が素材の全体を見て残した区間と、`find_highlights` と同じ処理の区間を比べる
「グループを保つ」（#437）は、映像・音声・テロップを束ねた作品をカットして、束ねが残ったかを数える

台本は `tools/eval_tasks.py` 段は 2 つ

- **道具の段**（`run`）AI を通さず、編集の道具が使う処理を直に呼ぶ 決まった結果が出て無料
- **AI の段**（`ai-run`）本物の編集画面を開き、AI アシスタントに決まった指示を出して数える 今はグループの課題だけ
  素材の名前・字幕・絵が Claude Code を通して Anthropic へ渡り、回すたびに使う量がかかるので、`--allow-send` を
  付けたときだけ回る 結果は `eval/results/ai.jsonl` に足す

## 決まり

- 素材・正解・直す用の .sme は**リポジトリの外**のフォルダに置く リポジトリの中を指すと台本が止まる
- リポジトリでは素材を番号（E04 など）だけで呼ぶ 番号と実物の対応表は外のフォルダの `manifest.json` だけに書く
- リポジトリに入れるのは、台本・課題の定義（`eval/tasks.json`）・数えた結果（`eval/results/tools.jsonl` と `eval/results/ai.jsonl`）だけ
- 結果を書く前に、台本が素材の名前・置き場のフォルダ名・日本語の文が混じっていないかを確かめる 混じっていれば 1 行も書かずに止まる
  名前を照らすのは、引数から来うる値（`params`）と数（`metrics`）の値だけ 日時・版・コミット・段・番号・課題・状態・理由は
  台本が自分で作る値なので、英数字だけかどうかの形だけを見る（年のフォルダ `2026` や `export` という名のフォルダでも止まらない）
- 結果の行と正解のファイルは標準の JSON だけで書く `NaN` や `Infinity` は書かない
  道具の値の引数（`--padding` など）に `nan` や `inf` を入れると、走らせる前に何がいけないかを出して断る
  数えた値が有限でないとき（無音の音量の `-inf` など）は `null`（測れない）と書く
- 場面の値は、アプリの場面検出が受け付ける範囲だけを使える `--scene-threshold` は 0.02 から 1.0、
  `--min-scene` は 0 から 600 秒（0 は寄せずにすべて残す） 範囲の外は走らせる前に断る
  `0` を渡したときも既定値に置き換えず、渡した値で数えて結果の行に書く
- `--asr-model` には、モデルの名前（`large-v3` など）・Hugging Face の名前（`Systran/faster-whisper-large-v3` など）・
  手元のモデルの置き場を渡せる 置き場を渡した回は、結果の行に場所を書かず `local-model` と書く
  結果の行に書けない値（日本語や素材の名前が混じった名前など）は、字幕起こしを走らせる前に何がいけないかを出して断る
- 使う素材は本人が自分で撮った・作った物だけ 本人が候補を見て決めた
- Issue・PR・コミットに素材の名前や置き場を書かない

## 用意

1. 外のフォルダを作る（本人の機械での置き場の例は `J:\sashimono-eval` 台本に既定の置き場は無く、
   下の 2. で必ず指す 指さないと台本は止まる） 中に `manifest.json` を置く

   ```json
   {"E04": "D:/どこか/素材その1.mp4", "E05": "D:/どこか/素材その2.mp4"}
   ```

   相対の場所は、このフォルダから読む
2. 環境変数 `SASHIMONO_EVAL_DIR` にそのフォルダを入れる（または、命令ごとに `--dir` で指す
   例 `.venv\Scripts\python.exe tools\eval_tasks.py run --dir J:\sashimono-eval`
   `--dir` は命令の前に置いても後ろに置いてもよい 両方に置いたら後ろの値を使う）
3. 字幕の課題には字幕起こしの部品（faster-whisper）が要る 開発の環境（.venv）には入れず、
   配布版のアプリが画面のボタンから入れた部品（`%LOCALAPPDATA%\Sashimono\runtime`）を読む
   部品が無い機械や、別の Python 向けに入れた部品しか無い機械では、字幕の課題の下書きを作らず、
   `run` では `no-answer` で飛ばす 書き出しの課題は字幕を焼き込まずに書き出す
4. 書き出しの課題は GPU（OpenGL 4.3）が要る 書き出した動画は外のフォルダの `exports` に残る

## 流れ

```
.venv\Scripts\python.exe tools\eval_tasks.py draft          # 仮の正解と直す用の .sme を作る
（本人が .sme を開いて直す 下の「正解を直す」）
.venv\Scripts\python.exe tools\eval_tasks.py adopt E09 scenes   # 直した .sme を正解にする
.venv\Scripts\python.exe tools\eval_tasks.py run            # 道具を走らせて比べ、結果を足す
.venv\Scripts\python.exe tools\eval_tasks.py ai-run --allow-send   # AI の段（グループ）を回す
.venv\Scripts\python.exe tools\eval_tasks.py report         # 課題ごとに前回との差を出す
```

`run` には `--silence-threshold-db` や `--scene-threshold` などで道具の値を変えて回せる
既定値を変えるか迷ったときは、変える前と後で 1 回ずつ回して差を見る

1 つの課題が途中で失敗しても（GPU の無い機械の書き出し・検査の時間切れなど）、その課題の行を
`"status": "failed"` にして次の課題へ進む 理由は固定の `export-error`（書き出し）・
`asr-error`（字幕起こし）・`tool-error`（ほかの道具）だけを書き、例外の文は書かない（素材の置き場が混じりうる）
字幕起こしが失敗した素材では、それを使うあとの課題（書き出しなど）でやり直さず、同じ `asr-error` にする
素材のファイルが無ければ（外付けのドライブを外した・名前を変えた）その素材の課題をどれも `no-material` で飛ばし、
素材が読めなければ `tool-error`、正解のファイルが読めなければ `answer-error` にして次の素材へ進む
`draft` も同じで、読めない素材や下書きを作れなかった課題は飛ばし、ほかの素材と課題の下書きは作る
正解のファイルは書き終えてから置き換えるので、書く途中で落ちても前の正解が残る

結果のファイル（`eval/results/tools.jsonl`）は足して書くので、書く途中で落ちると最後の行だけが
切れて残ることがある 最後の行が JSON として読めなければ、その行を飛ばして読み、飛ばしたことを画面に出す
次に `run` で足すときは、切れた行を外し、改行で終わっていなければ改行を足してから書く
（切れた行と新しい行がつながって、新しい行まで読めなくなるのを防ぐ）
途中の行が壊れているのは切れたのではないので、行の番号だけを出して止まる（行の中身は出さない）
その上には足さないので、壊れた行を直すか消してから回し直す

### 状態と理由

結果の行の `status` と `reason` は、下の表の値しか書かない 表に無い値の行があれば、名前が混じったときと
同じく 1 行も書かずに止まる（理由は名前の照らしを外しているので、決まった値に絞って素材の名前が入る道を塞ぐ）
台本の一覧（`tools/eval_tasks.py` の `STATUSES` と `REASONS`）と食い違わないことを試験が見る

| 値 | 種類 | 意味 |
|---|---|---|
| `ok` | 状態 | 数えた |
| `skipped` | 状態 | 数える前の事情で飛ばした |
| `failed` | 状態 | 数える途中で失敗した |
| `no-material` | 理由 | 対応表に無いか、素材のファイルが無い |
| `no-answer` | 理由 | その課題の正解が無い |
| `no-tool` | 理由 | 道具の段にその課題の道具が無い（話の区切り） |
| `asr-missing` | 理由 | 字幕起こしの部品が入っていない |
| `asr-error` | 理由 | 字幕起こしが失敗した |
| `export-error` | 理由 | 書き出しか書き出した動画の検査が失敗した |
| `tool-error` | 理由 | 素材を読めなかったか、ほかの道具が失敗した |
| `answer-error` | 理由 | 正解のファイルを読めなかった |
| `no-consent` | 理由 | AI の段を送る物の同意なしに回そうとした（案内を出して止まるので、結果の行には書かない 決まった名前として持つだけ） |
| `ai-error` | 理由 | AI の段の会話が失敗した（ログインの切れ・道具の例外など） |
| `ai-timeout` | 理由 | AI の段の指示が上限の秒までに終わらなかった |
| `ai-no-cut` | 理由 | AI の段で、AI が何も切らずに終えた（グループが残ったのは切っていないから 数は残すが成功と並べない） |

### 仮の正解

本人が直すまでは、道具の下書きをそのまま正解（仮の正解）として使う（場面ごとに切る課題を除く 下を見る） 結果の行には
`"provisional": true` の印が付き、`report` の右端に「仮」と出る

仮の正解と同じ道具の結果を比べると、数は 1.0 に近くなるのが当たり前 その数は精度ではなく、
「前の回から道具の結果が変わったか」の目安にしかならない 本人が直した課題から、本当の精度になる

`draft` をもう 1 度走らせても、作ってある仮の正解は飛ばす（作り直すなら `--force`）
本人が直して取り込んだ正解は、`--force` でも書き換えない

場面ごとに切る課題（T3）と見どころを選ぶ課題は仮の正解を作らない（#345 の決まり） 道具の下書きから直すと、
直し忘れがそのまま正解になって正解が道具の癖に寄り、直す前の回は道具と道具を比べて F1 が
実際より高く出る `draft` は目印の無い .sme だけを作り、本人が素材の全体を見て一から目印を置いて
`adopt` するまで、`run` は `no-answer` で飛ばす 前の版の `draft` が残した場面の仮の正解は、
次の `draft` で外し、`run` でも比べない 目印を置いている途中の .sme は `--force` でなければ上書きしない

`report` も、場面の課題では仮の印の付いた行（前の版が道具の下書きと比べて数えた行）を数にも前回にも使わない
人の正解で数えた行がまだ無ければ「まだ人の正解が無い」と出す 結果のファイルの行は記録として消さずに残す
ほかの課題の仮の行は今までどおり数に使い、右端に「仮」と出す

## 正解を直す

`draft` は、外のフォルダの `drafts` に課題ごとの .sme を作る 名前は `<番号>_<課題>.sme`
Sashimono Edit で開いて直し、上書き保存してから `adopt` で取り込む 課題ごとに直す所は次のとおり

| 課題 | 開く物 | 作品の中身 | 直す所 |
|---|---|---|---|
| 無音を削る | `E04_silence.sme` など | 道具が無音を詰めた後のタイムライン | 残すべき所まで削れていたら、クリップの端を伸ばす 残っている無音は分割して消して詰める 話の頭と終わりが欠けていないかを聞いて確かめる |
| 話の区切りで分ける | `E05_talk.sme` | 素材をそのまま置き、長い間の所に「区切り」の目印 | 話題が変わる所に目印を置く 話題の変わらない所の目印は消す 文の区切りではなく話題の区切りを付ける |
| 場面ごとに切る | `E09_scenes.sme` など | 素材をそのまま置き、目印は置かない | 素材の全体を見て、場面が変わる所に「場面」の目印を一から置く 目印は新しい場面の最初のコマに置く |
| 見どころを選ぶ | `E05_highlights.sme` など | 素材をそのまま置いただけ | 素材の全体を見て、切り抜きに使いたい所だけを残し、ほかは分割して消す（詰めても詰めなくてもよい） |
| 字幕を付ける | `E04_subtitles.sme` など | 素材に字幕起こしの結果が付いた作品 | 字幕のパネルで、聞き違いの文字と、字幕の頭と終わりの時刻を直す |

- 素材のクリップは動かさない（動かしても目印の位置は素材の秒に直して読むが、迷う元になる）
- 目印の名前と色は数えない どの名前でも 1 つの区切りとして読む
- 別の名前で保存したときは `adopt E09 scenes --from <直した .sme>` で取り込む
- 1 本の 1 課題を直したら、その場で `adopt` してよい 全部を直すまで待たなくてよい

## 数え方

| 課題 | 主な数 | ほかに残す数 |
|---|---|---|
| 無音を削る | `iou` 残した区間の重なり（10ms 刻み） | `agreement` 残す・削るが合った割合 `edge_median` 正解の端ごとに一番近い道具の端までの秒の中央値（道具が 1 つも切らず端が無いときは `null` 測れない） |
| 話の区切り | `f1` ±1.0 秒の中で 1 対 1 に組む | `precision` `recall` 道具の段では数えない（道具が無い） |
| 場面ごとに切る | `f1` ±2 フレームの中で 1 対 1 に組む | `precision` `recall` |
| 字幕を付ける | `cer` 文字の誤り率（句読点と空白は数えない 長音符「ー」は語の一部なので数える） | `edge_f1` 字幕の頭と終わりの一致（±0.5 秒） |
| 見どころを選ぶ | `f1` 正解の区間に重なる道具の区間があれば当たり | `precision` `recall` と、無音と同じ `iou` `edge_median` |
| グループを保つ | `kept_share` 時刻の重なる別のトラックのクリップの組のうち、同じグループに居る組の割合（1.0 が全部残った 前半と後半が 1 つのグループにまとまったら 0） | `merged`（前半と後半がまとまったら 1） `pairs` `groups` `loose_clips` `cuts`（道具の段） AI の段は `removed_seconds`（切って詰めた秒 0 なら `ai-no-cut`） `ungroup_calls`（`ungroup_clips` を呼んだ回数）`ungroup_questions`（解く前の問いが出た回数）`questions` `tool_calls` `refused_irreversible` |
| 字幕を焼き込んで書き出す | `problems` 書き出した動画の検査で見つかった問題の数（正解とは比べない） | `count_<種類>` 種類ごとの数 `loudness` 音量（LUFS） `length_error` 長さのずれ（秒） `subtitle_clips` 焼き込んだ字幕の数 `export_seconds` `check_seconds` |

許す幅は `eval/tasks.json` の `tolerances` で変えられる かかった秒は、道具の処理（波形や
場面の解析・字幕起こし）を始めてから答えが出るまでを測る 書き出しの課題の秒は、字幕起こし
（同じ回の字幕の課題で済んでいれば 0）・書き出し・検査の合計

字幕起こしは、同じ素材・同じ版でも回ごとに少し揺れる（2026-10-20 に GPU で 13 分の素材を
2 回起こすと、1 回目を正解にした 2 回目の `cer` が 0.048 になった） 字幕の課題の差は、
この揺れより大きいときだけ変更の効果と読む 無音と場面は揺れない（2 回回して同じ数になる）

書き出しの課題の字幕は、同じ回の字幕起こしの結果をそのまま焼き込む（直した正解ではない）
書き出しの課題が見るのは、焼き込みと書き出しと検査の流れが崩れていないか（黒いコマ・音の欠け・
長さのずれが増えていないか）で、字幕の文の正しさは字幕の課題で見る

## グループを保つ課題（#437）

素材を頭から置き、真ん中で割って、前半と後半それぞれの映像・音声・テロップを 1 つのグループにした作品を作る
正解は持たない

- 道具の段は、その作品に無音カット（`jet_cut` と同じ命令）を掛け、グループが残ったかを数える 分割と範囲を切って詰める所の
  グループの分け方（#427）が崩れていないかを、実物の素材の切れ目の数で見る
- AI の段は、同じ作品を外のフォルダの `drafts/<番号>_groups_ai.sme` に置いて本物の編集画面で開き、AI アシスタントに
  「話していない間を詰めて、テンポよく見られるようにしてください 保存と書き出しはしないでください」とだけ頼む
  確かめの窓は AI のパネルの代わりに台本が答える 取り消せる編集は許し、保存と書き出しは断る グループを解く前の問いには
  〔解除しない〕を返し、ほかの問いには決めずに進めるよう返す 本人の設定（AI のモデル以外）は画面と同じ物を読む
  数えるのは、終わった後に組が同じグループに残った割合と、`ungroup_clips` を呼んだ回数・解く前の問いが出た回数
  （#428 で、解く前に尋ねる形と、断りの文から解除を勧める文を消した その効き目を AI を通して確かめる）

## 素材を増やす

1. 本人に候補を見せて、使ってよいかを聞く（自分で撮った・作った物だけ）
2. 外のフォルダの `manifest.json` に番号と置き場を足す
3. `eval/tasks.json` の `materials` に番号と課題だけを足す 名前は書かない
4. `draft <番号>` で仮の正解（場面は目印の無い .sme）を作り、本人に直してもらう
